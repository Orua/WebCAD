# AI怎样在WebCAD完成一个三维模型

多个配件、装配体或复杂产品先读[分批建模与交付](api.modeling.methods.staged-assembly)，先交规划，按实际确认或已授权范围分批执行。单个简单件不增加固定确认轮次。

这份指导负责建模判断。工具卡负责精确参数，两者不能互相替代。先读当前用户需求，按以下闭环推进；简单件可以几句话完成，不强迫用户填写大表。

## 一、把形容词变成结构与约束

先确定是复刻源件、按尺寸新设计、修改已有模型，还是只检查/导出。识别独立制造的部件、连续材料、孔洞、配合面、截面和预期输出。源图先定位正确产品/零件/版本和视图；照片补结构，标注控制尺寸；缺一个视图未必缺几何证据，多一个视图也不能解决相互冲突。

把关键量分成已标注、源实体测得、约束推导、用户允许假设、未知五类。推导量用公式计算，不凭感觉写坐标、半径或重量。直径与半径、总高与端面高度、轮廓R与截面R、实心与中空分别确认。不会影响本次结果的未知不拦住任务，会改变模型的未知必须解决。

## 二、选择能直接表达控制尺寸的构造

依据[构造选择](api.modeling.methods.construction-choice)判断等截面、旋转体、路径截面、多截面过渡。已有标准件先查可追溯模型，结构完全匹配时用具体模板；不能为了少调用工具把复杂结构改成近似形状。

把模型分为主体、去料/加料、定位组合、局部收边、图案。每项写清输入、依赖和检查点。例如带孔板是外形/厚度→孔型/孔位/深度→当前选边→R/C，不是先随便拉一块再靠试切得到近似。先在草图里包含准确内外轮廓也可能更稳，顺序由几何决定。

## 三、先建立可核查基准，再操作

以安装面、对称中线、轴线、端面或真实路径起点作为功能基准。说明原点、轴向、局部/世界坐标与长度/角度单位。外观网格、精确实体、工程配方和导出物各有用途；不把显示旋转当实体定位，不把材质颜色当物理材料。

通过授权页面通道connect当前文档，检查blockers和卡片；模板只读目标template卡。写入带新鲜context、明确refs和幂等键。用同批次回执引用后续对象，改形后重查拓扑。确定性坐标/阵列/单位换算交给脚本，AI负责来源、路线与歧义判断。

## 四、每种特征用对应证据验收

外形查bounds；孔查当前圆边/孔壁、中心、层位和贯穿/盲底；连接查材料和实体数；局部R/C查目标范围和真实几何；改动查不变量。几何正确、画面匹配、字节生成、写盘和部署分别报告。无相应测量接口的要求标未验证，不能把总量或视觉作为局部证明。

## 五、失败时选择诊断工具，不轮流试工具

先定位第一个失败步骤及当前已提交状态，再读[诊断表](api.modeling.problems.diagnosis)。参数错读卡/核单位；孔不见查相交/方向/深度；圆角失败查边归属、小面与余量；扫掠/放样失败查截面/路径/对应关系；断线先查原回执。每个真实候选共享一次基线加一次有机制证据的替代，不能换key无限重跑。

修复应保留用户尺寸、孔数、字形和材料要求。若必须改变设计才能完成，说明变更及原因，等待设计决定。原工程仍可用时保留，不以重建清空、不支持的自动展开或第二内核掩盖失败。

## 六、按用途交付

工程继续编辑、精确STEP交换、网格打印、切割轮廓和工程图是不同交付。读取实际导出文件而非生成器自报；带条件给出尺寸/制造结论。外部查询/下载属于宿主能力，切片/打印/供应商下单属于另一个授权动作，不能因完成模型就自动执行。

按任务选分册（agent-routing.json 的 modeling.* 路线）：源图复刻→source-reconstruction；轮廓→profiles-2d；工程图→drawings；制造检查→manufacturing；打印→printability；标准件/重复件→part-reuse；材质/克重→material-properties。路线候选来自catalog，不等于机器已理解所有几何。方法来源与接入边界见 api.modeling.sources。
