# api.modeling.methods.artifacts-and-dependencies

# 来源、当前工程与派生结果

参考text-to-cad的模型契约/项目组织/迁移资料，先区分可编辑来源和派生物。在它的体系中Python通常是生成源；在WebCAD中当前页面文档和真实特征/导入形体才是执行依据。不能要求用户准备Python，也不能把导出的STEP当作自动保留原参数历史的工程。

用户给的STEP/BREP是只读来源；模型库模板、图案源与已保存工程各自有版本和身份。files.import的参数、单位与定位按当前卡，mesh导入尤其须显式单位与幂等键。导入后检查实际尺寸/姿态，而不是仅相信源文件名或模板名称。已有源配方时修改源；只剩最终形体时核实可执行的局部加工，不能调用不存在的feature.edit。

依赖改变后检查受影响下游：例如板加厚会改变顶面Z，基于旧顶面坐标的孔入口/LOGO落点不能不经核对继续复用。只修改一个子部件不意味着所有上游组合和缓存结果已经更新。通过当前状态、特征绑定和回执判断，而不是根据上一次显示或缓存ID猜测。

保存工程、导出交换文件和模型资源是三种交付。用户还要继续改尺寸时说明当前工程保存语义和实际可编辑性；导出文件用于交换，不承诺保存undo、配方、装配约束或制造标注。旧输出被重命名后仍可能留存，只有明确属于本任务且已核验的旧派生文件才可清理，原始来源始终保留。

遇到版本/Schema不兼容，读当前页面契约和具体错误，更新受影响知识或走已有兼容入口；不能手改版本号、伪造哈希或忽略丢失的外观/数据。源码版本、页面buildId、几何revision、文件SHA256分别记录，任何一个相同都不能替代其余一致性证据。

正常例：将板厚3改4后重查顶面及孔入口和LOGO依赖。边界例：重新导入STEP仅得到最终形体，没有旧撤销历史，保留来源并选择支持的加工，不能声称恢复了源配方。
