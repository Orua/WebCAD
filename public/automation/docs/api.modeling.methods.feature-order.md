# api.modeling.methods.feature-order

# 安排步骤与依赖

先形成决定外形的主要结构，再加工依赖它的孔/槽，最后处理需要当前面边的局部特征。LOGO通常放在主体和收边之后，减少它使面边碎化对选取的干扰；这不是禁止早做LOGO。若轮廓中已经准确包含R角，可先拉伸该轮廓，避免不必要的3D收边。

把计划写成部件和特征依赖：主体→孔；主体→柱脚定位→明确融合；当前目标面→LOGO。独立制造或移动的零件保留独立对象，不因外观接触而union。融合后原部件可能不再有独立对象身份，角色意图应保留在命名和验证要求中。

重复同规格孔先算所有中心点，用multiHole等原子操作；异孔径/不同底型分别加工。多个不相交刀具可按支持能力合批；重叠刀具或依赖前一结果时允许分段。加长刀具只为覆盖目标材料，长度根据目标厚度与方向确定，不能贯穿并误伤后面的装配件。

WebCAD的addMany仅用于其当前允许的操作：读api.feature-plan和feature.addMany卡，不自行把LOGO/选边加工塞进去。需要先查询拓扑的步骤必须分段：执行→获得新revision→查询→选择→加工。run本身atomic=false，前序成功不会随失败自动回滚。

提交后检查点按风险设置：基础简单体只读关键尺寸；拓扑加工前后检查目标和保留结构；不要每一步都做全件重测。一个相关回归足够，出现具体失败再补对应检查。
