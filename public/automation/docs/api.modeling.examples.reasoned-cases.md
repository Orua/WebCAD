# api.modeling.examples.reasoned-cases

# 从需求到方案的完整例题

以下均是人为定义的测试条件，不能作为真实产品默认尺寸。tools/中有真实卡，scripts/recipes.mjs提供可检查调用；不是从这些尺寸推导工厂标准。

## 例1：安装板上两通孔

需求：矩形板40×20×3，XY角点原点；孔Ø4，中心(10,10)、(30,10)，沿Z贯穿。首先计算r=2、孔距20；原外形必须保持。若源件有圆角则另确认，不能沿用旧版安装板模板的R2。选择box+multiHole而非mountingPlate：后者带其自身中心原点/外轮廓参数，只有完全对应才用。

计划：box明确world/model-origin→同回执body上multiHole，入口Z=3方向-1，深度3→测量。验收体积2400-24π，外形40×20×3，两个中心在指定坐标；圆孔上下口共四完整圆边。正常：体积和孔中心同时满足。边界：若只查radius=2，外R2也可能命中，须加完整圆长度/中心/层位；只有体积正确不能通过。

## 例2：给已有板开盲孔

条件：30×20×3精确板，顶面Z3，点(15,10)，孔Ø4，平底深1。选择hole(r2,depth1,z3,direction-1)，不选通孔向导through=true。必须保持底厚2及外形，验收体积1800-4π、底面Z2的圆边/平底证据和孔中心。

如果孔不见：先查当前body、入口和方向，不增加深度“试试”。如果用户只说“开孔”未给深度或通孔含义，保留方案候选并询问，不能默认为贯穿。

## 例3：一只轴套与带头铆钉

轴套条件：外径12、内径8、高3且同轴直壁。tube可直接表达，验收体积60π和内孔r4上下边。内径大于外径是输入冲突，不自动交换。若需求变成带帽、腰槽、盲孔的铆钉，tube和直柱均不足；分解轴向截面，用profileRevolve或完整匹配模板，再补非轴对称特征。正常路线取决于结构，而非“铆钉”名称。

## 例4：板件四条竖边C0.5

条件：30×20×3矩形板，只倒四条竖边，其他边不变。queryGeometry用line、长度3、方向/端点确认，requireUnique:false、expectedCount:4；选择chamfer(distance0.5)，不使用fillet。验收外包络保留、所选四角切去材料以及原孔不变；R是否存在不能靠体积判定。固定R0.5则另选fillet分支，失败后不能悄悄用C0.5代替。

## 例5：一段弯曲方线框

来源给定中心路径和5×5方截面，框内宽/高及转弯R为已标注数据。选择profileSweep，因为控制量是路径和截面；若只提供外轮廓，先换算/确认中心路径，不能将外R直接作为中心R。截面起平面法向应平行路径起点切向。正常：截面尺寸、内开口、连接都符合来源。边界：若扭转先查截面法向/绕向与路径，不改成圆线或圆环模板。本例构造方法已映射真实工具，未以简单体回归冒充源件已验收。

## 例6：已有模型加深孔后连接中断

用户要求将深1盲孔改深1.5，底片和其他孔保持。先getState/getHistory确认原特征可编辑；若仅剩导入最终形体，就不能调用不存在的原feature。提交后断线，先getBatchReceipt查原key和当前revision，确认是否已提交；不要重开新key再钻一次。

正常：深度1.5、底厚1.5，其余不变；未知结果不算失败也不算成功。若任务后来确知失败且原工程保持，可规划剩余加工。undo仅在明确末位操作归本任务时使用。

## 例7：恒深字母与浮雕图像

审核后的字形轮廓含内孔、明确大小与位置，要求凹0.2，走logo恒深轮廓路线；原图为渐变高度图时应先澄清是否要浮雕，不能将灰度阈值后的轮廓当等价源。先reviewLogo，再查当前平面与落点。保留字形、孔环、深度、底片；没有独立深度或源轮廓复核就标未验证。

## 例8：导出选择

“给精确STEP”先验证BRep，再files.export(format:step)，files.read取得真实字节；生成和宿主落盘分开。“导出STL”必须走stl分支，不能因导出两字进入STEP。未给格式时询问，mesh不能被文件后缀升级成精确曲面。导出检查按任务需要，不默认做保存/上传/部署。
