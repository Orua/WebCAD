## 0. 任务指令：完善工具，不是修复某一个产品

**本任务交付对象是 WebCAD 的通用圆角／圆润工具。必须修改正式工具、内核实现、页面入口、公开 API、历史重算和测试；不能以做出某个产品、写诊断脚本、增加失败提示或完成参数穷举作为交付。**

产品复盘只用于归纳失效类型，最多作为一个可选回归样本。生产代码禁止包含产品编号、产品文件路径、专用坐标、固定边号／面号、只匹配某产品的尺寸或短边补齐规则。没有产品源文件也应能完成全部便携式通用测试。

以下为**待实现的设计要求**，不是已完成能力，也不是对任意曲面、任意半径都能成功的承诺。严格恒 R、变 R、宽度控制的平滑过渡有不同几何定义，必须分别实现和验证，不能互相冒充。

## 2. 产品定义：一个主入口，三种真实模式

在现有“修饰”分组使用一个主入口 **“圆角／圆润”**。已有“圆角”“平滑过渡”“整件圆边”的快捷调用可以预选不同参数，但不再各自维护独立算法。斜角不必混进该面板，保留原入口并复用必要基础设施。

| 模式 | 用户主要输入 | 几何含义 | 不允许的替代 |
|---|---|---|---|
| 标准 R 角 | R 值、目标范围 | 以指定半径生成圆角带；公差内验证 | 失败后自动减小 R、改宽度或改成自由曲面 |
| 变 R 圆角 | 有方向边链、沿链位置和 R 值 | 半径随规定位置变化，沿链连续 | 每条边各自随意编号后插值；拿普通截面放样冒充指定半径规律 |
| 平滑圆润 | 两侧支撑面、两侧过渡宽度、端点规则 | 在限定区域替换为与支撑面接顺的过渡面，首版目标 G1 | 没有半径定义却报告“精确 R”；只平滑显示网格或法线 |

“G1”在界面用“相切接顺”解释：接缝两边没有明显折向；它不同于曲率连续 G2。首版不展示未经验证的 G2、任意全圆角或多面自动曲率连续选项。

**整件只是作用范围，不是第四种万能算法。** 首版整件范围采用统一恒 R；变 R 按明确边链设置，宽圆润按明确面组设置，不对整个实体任意推断参数。

### 2.1 首版必须实际支持的通用几何族

A. 原生严格圆角：常规凸边、凹边、解析／规则曲面交线、开放和闭合链，以及内核能处理的多边交汇。

B. 变 R：直边和多段相切边链的起止半径；多站点正半径规律。闭合链必须处理首尾一致性；不能把闭合链切口藏起来。

C. 同设计备用构造：两平面沿直交线的精确圆角；一个平面与垂直于它的线／圆弧轮廓拉伸侧壁之间的恒 R 过渡。至少实现闭合轮廓，以及明确自然终止面的开放轮廓。它是按几何族判断，不按产品判断。

D. 宽圆润：两平面公共直边的对称／非对称宽过渡；平面与上述解析拉伸侧壁之间的规则宽过渡；四边界、无孔洞、无奇异点的局部相切补面。

E. 收口：自然终止、沿唯一相切链延续、在已有明确限制面终止；对兼容四边界局部区域完成相切接顺收口。无兼容边界时必须给可选择的作用范围，不能承诺凭空消失。

复杂高价顶点、任意自由曲面网络、跨多个周期接缝、跨孔面片、全局去圆角、三个任意面全圆角、G2 自动补面不属于首版必须全覆盖范围。**但是 A–E 不能全部通过返回“不支持”来验收；正向必过样例见第 13 节。**

## 3. 选择、传播、端点：把几何意图定义清楚

### 3.1 选择范围

同一请求只允许一种范围：

- 选边：当前单个实体的明确边集合。
- 面边界：选中面与邻面的边界；内环是否包括必须明确，默认显示并包括，允许显式排除。
- 面间公共边：只处理两个面组之间的公共边，不等于这几个面的全部边界。
- 整件锐边：所有需要处理的有效锐边，支持显式排除边／面区域，并显示排除数量和原因。

宽圆润初始支持同一实体内存在公共边链的两侧面组。非相邻面、多个可能连接区、同侧重复面、跨实体请求不能随意猜测，返回候选或具体冲突。

复用已修正的屏幕命中逻辑，不再跨实体吸附。不依据屏幕朝上判断面方向，不以边长最短、离某坐标最近等启发式自动选中产品目标。

### 3.2 相切传播要区分两件事

- **面之间相切**：这条分面线可能本来就不需要倒圆。
- **边链在顶点处相切**：每一段仍是锐边，但几段锐边沿一个方向连续，可以作为一条圆角链。

不可把二者混成“相切边全跳过”。

提供 `selected-only` 和 `tangent-chain`。首版 UI 默认显示相切链传播后的完整高亮，用户可关闭。内核实际生成轮廓超出已允许范围时，不可悄悄修改：返回 `SCOPE_EXPANSION_REQUIRED` 及新增边。不能假定 `Add(edge)` 只会加工一个数字编号。

整件或多边请求中，互相影响的边必须在同一个构造上下文处理交汇。禁止用“每条边单独做一下”作为默认通用解决办法。完全不相交的分组可以在临时候选内分步构造，但每步重新解析引用，全部验证后一次提交。

### 3.3 端点模式与验收要求是两个维度

| 端点方式 | 定义 | 首版要求 |
|---|---|---|
| `natural` 自然终止 | 在原几何允许的现有终止面收尾 | 必做；普通终止边可能是锐边，必须标识，不能叫整区接顺 |
| `continue` 相切延续 | 沿唯一相切链继续，直到已声明限制 | 必做；展示实际扩展范围和终点，不无限跨区域 |
| `stop-face` 指定终止面 | 明确的当前实体限制面，交线须处于该面有效区域 | 首版支持已有可用限制面的规则情况；不是向任意无限平面硬裁 |
| `smooth-connect` 相切接顺 | 在已限定的端部区域接入指定邻面／已有过渡面 | 必做规则四边界实现；边界不兼容时失败或提出扩大范围的候选 |

另设验收选项：

- `standard`：两侧圆角带要接顺；已声明的自然终止轮廓可以锐接，结果标注其范围。
- `smooth-region`：作用范围内新增交接缝，包括两端，均须通过接顺检查；不允许通过“它落在未选面上”放行新台阶。

默认：标准 R 和变 R 用 `standard`；平滑圆润用 `smooth-region`。UI 必须展示区别，不能暗中把后者降为前者。用户可以明确选择普通终止，但不能把未通过的严格结果自动改标签提交。

指定终止面不是简单增加一个 UI 字段。不得假设内核存在未核实的 `SetStopFace` 一类接口；需要修剪／替面时必须真实实现，不能忽略该参数后调用普通圆角。

闭合链没有起止端模式；变 R 闭合规律应满足首尾值和所选连续阶次相容。零端半径首版不作为普通选项，不用任意极小 R 伪造零半径收口。

## 4. 实现结构：共用编排，不同构造器

建议新增目录，名称可贴合仓库现有结构调整，职责不得丢失：

```text
src/modeling/rounding/
  contracts.js          # 新请求、持久配方、回执 schema
  topology.js           # 邻接、物理点法向、边链方向、端部邻域
  planner.js            # 范围、传播、几何族、预算、策略决策
  native-fillet.js      # 原生恒 R／变 R + 实际轮廓和历史映射
  analytic-round.js     # 有明确适用条件的精确解析备用构造
  surface-blend.js      # 宽度／边界控制的相切过渡和局部替面
  endpoints.js          # 自然终止／限制面／相切接顺规则
  validation.js         # 实体、半径、接缝、材料、局部影响范围
  report.js             # 有界、可序列化诊断和验证报告
```

`src/edge-blend.js` 与 `src/smooth-transition.js` 保留兼容导出，改为调用共享实现或旧版语义适配器；不要立即删除公共函数导致其他检查工具失效。循环依赖要消除：共享拓扑不能再通过“旧平滑过渡构造文件”被所有新算法反向引用。

整体执行：

```text
输入／当前引用
 → 解析设计意图和作用范围
 → 建立实际边链与端部条件
 → 生成有界构造计划
 → 在隔离候选上执行
 → 统一验证
 → 输出预览＋报告
 → 原子提交一个特征
```

计划、参数和验证应由同一组模块服务 UI 与 API。不要实现“人工走新算法、AI 仍走旧 fillet”的两套路径。

## 5. 原生恒 R／变 R 的实施要点

### 5.1 恒 R

对解析后的轮廓统一设置明确半径，构造前后核对实际传播范围。保持 `Build → IsDone → Shape → 统一验证`，失败部分形状仅作诊断。

从内核构造历史建立源边／顶点到生成面、源面到修改面的映射，用于后续接缝检查和结果报告；映射不足时说明证据不足，不能以“结果面数增加”证明选中的边已全部加工。

### 5.2 变 R 的位置定义

公共接口使用**所选有向边链累计弧长的比例** `s ∈ [0,1]`，而不是原始曲线参数，也不是每条边各自等分。

每条链必须有：链标识、明确起点、方向、是否闭合、累计长度、按方向排序的边及各边弧长区间。关闭自动传播后不得悄悄改变链总长。

站点规则：

- 2～16 个站点；包含 `s=0` 与 `s=1`，位置严格递增，R 为正有限数。
- `linear` 用于明确的分段线性规律；`smooth` 使用不超出相邻站点值域、正值、可验证的一阶连续插值。首版可用保形三次 Hermite 规律，不用无约束三次样条导致 R 过冲或负值。
- 同一圆角轮廓收到冲突半径定义时返回 `RADIUS_LAW_CONFLICT`，不能以循环后写入者覆盖前者。
- 反向链须将站点变为 `1-s` 并重新排序；不能只反转边列表。
- 闭合规律必须声明切口位置；首尾值相等，平滑规律首尾导数相容。

**内核适配器必须验证：公共弧长站点与实际 law 参数域如何转换。** 原生接口可能作用于整条相切轮廓，而不只是传入的种子边。用不等长边和反向链测试读回半径位置，不能仅凭重载名称认定正确。

### 5.3 WASM 能力核查与缺失接口处理

在实际锁定 WASM 上执行小形状 smoke test：恒 R、两端 R、多站点规律、构造历史、面约束补面、修剪缝合和自适应体积。区分“存在符号”“重载可调用”“输出通过几何验证”。

不得只看在线 C++ 文档、TypeScript 声明或 `typeof` 就报告支持；也不得凭类名不存在便推断 OCCT 算法不存在。

确需补充绑定时，优先在已锁定内核源版本增加少量已使用接口或一个稳定参数包装器，保留可重建脚本和版本标识；不为本任务无证据地升级所有依赖。若构建环境确有阻碍，提交可复現阻碍和已完成分项，不假造可调用 API，也不把必做变 R 标成未支持后宣告全部完成。

## 6. 同意图策略链：提高成功率，而不是偷改要求

对严格恒 R／变 R，默认策略：

```text
① 原始几何＋原始请求，原生构造
② 仅在诊断支持时，受控等价拓扑整理后重试原始请求
③ 若满足已实现的解析几何族，使用同半径解析备用构造
④ 失败：保留原件，返回具体原因和可选新方案
```

①～③必须保持请求 R／规律、允许的范围、锁定区域和精度要求。不能自动从恒 R 跳到变 R 或宽圆润。

默认同意图尝试最多 3 个不同、可解释的候选；重复同样输入不算新策略。较小 R 试算改为用户／AI明确请求的“查看替代参数”，不在每次拖动预览时重复最多 11 次构造。建议候选使用离散验证，不假定圆角可行性对半径全局单调，不写成“最大 R”。

### 6.1 受控拓扑整理

允许在候选副本中尝试合并真正同域、冗余的面／边，修正有证据的表示问题；必须记录受影响区域、容差和引用映射。不能把不同半径的弧、小夹角、短线一律合并或删除。

必须区分：

- 等价表示整理：不主动改设计曲面，在约定模型精度内复核。
- 几何修复：移动端点、重新拟合曲线、改半径、移除真实面。属于新设计方案，需要用户明确授权，不是圆角工具的默认隐式前处理。

不要假定 `shape.clone()` 是可安全原位修复的深拷贝。对会修改共享底层拓扑的操作，使用经实测隔离的深拷贝／序列化重建或独立试算 Worker；测试源实体在成功、失败、取消后均未被改变。

### 6.2 解析备用构造：首版做成真正的第二条几何路线

#### 几何族 A：两个平面、直公共边

在公共边法截面内，根据两条支撑线及实体所在侧，求与两线相切的指定 R 圆。把圆弧沿公共直边生成圆柱过渡，按真实支撑面范围和端面裁剪，再替换局部面或形成经验证的材料操作。

实现要点：

- 通过有向偏移线／平面的相交求圆心，候选按实体内外分类选择，不能固定“右上象限”。
- 覆盖非 90° 夹角。凸角与凹角按材料语义分别处理，不要求所有圆角都减料。
- 接点必须在允许面域内，遇到孔洞、面边界、狭小空间不得延长模型逃避限制。
- 新面、两侧裁剪面、端面需共享一致边界；布尔方式和替面方式都必须经过统一验证。

#### 几何族 B：一个平面＋与其正交的解析拉伸侧壁

适用性必须由 BRep 几何证明，而不是放宽到“看起来约 90°”：公共轮廓在同一平面，侧壁确为沿该平面法向的规则拉伸；轮廓由方向一致、相切接续的直线／圆弧构成。

使用轮廓的有向平面法线构建恒 R 截面和相应中心轨迹；直线段可形成圆柱过渡，圆弧段形成对应回转过渡。维护连续随动标架，检查偏移轮廓奇异、自交和非局部碰撞。

不能照搬“2～8 条边、自动补某条短线、固定外延 0.4”等案例限制。数量上限只作为统一资源预算，连接必须基于真实拓扑；自动补入真实连接边也必须在预览显示并得到选区授权。

首版优先闭合轮廓，再实现端部落在明确限制面的开放轮廓。开放切削体封口仍在实体内部、导致产品出现新台阶时，不能提交严格接顺结果。该路线只处理已证明的恒 R；任意空间曲面或变 R 不可直接复用四分之一圆扫掠公式。

**验收须强制分别运行 native 与 analytic 两种策略，比较半径、材料和接缝。不能把“再次调用 native”包装成 analytic。强制策略开关只供内部测试，不必暴露普通用户。**

## 7. 宽度控制的平滑圆润：不是换个名字调用 fillet

### 7.1 参数与几何定义

两侧支撑面记为 A、B。输入 `widthAMm`、`widthBMm`；相等为对称，不相等为偏向一侧的宽过渡。

宽度定义为：在沿导引边链的局部法截面中，从原公共交线点沿相应支撑截面曲线走到接合轨线的距离。不是 UV 参数差，也不是屏幕距离。遇到截面多分支或切点奇异，改为要求明确接合轨线，不能任选最近分支。

新面应与 A、B 沿两条接合轨线相切。端部按第 3.3 节处理。过渡区内可以改变表面，区外必须保持，且不可改变未授权的孔、字、邻近凸台等结构。

不返回单一 R 值；报告输入宽度、实际接合轨线、相切误差和影响范围。可以测量曲率作辅助，但不能把最小曲率半径当作“本工具使用 R”。

### 7.2 第一条可直接实现的构造：两平面宽过渡

对公共直边的法截面，先确定 A/B 两个接合点和相应切向。用端点及端部切向约束构造规则三次 Bézier 过渡，再沿公共直边拉伸，修剪并回接原实体。

控制点定义：

```text
P0 = A 侧接合点
P3 = B 侧接合点
P1 = P0 + hA · tA
P2 = P3 - hB · tB
```

`tA/tB` 是沿过渡前进方向的单位切向；`hA/hB` 必须为正。首版使用一个确定、版本化、尺度相关的手柄规则，例如分别取对应接合距离的 1/3，并验证曲线无自交、无回折、位于允许过渡区。此系数是新算法的设计参数，不是某产品修复经验；不得在失败后随机扫一批系数挑好看的。

该构造的价值是：宽度与偏向可控，且在这个规则几何族内可以直接建立端部切向条件。它不是圆弧，因此名称和回执必须是宽圆润。不得把控制多边形显示为实体表面。

### 7.3 规则曲边与局部四边界补面

对平面＋规则拉伸侧壁，沿真实公共轮廓生成接合轨线与切向条件，构造相切过渡带。若使用分段 B 样条拟合，必须保留轨线约束，并对段间接缝验证，不能仅加密截面后宣称接顺。

一般局部补面的流水线必须完整实现：

1. 确定两条支撑接合轨线及两条端部边界；形成无分叉、无孔的有向闭环。
2. 在支撑面中建立有效 p-curve／修剪边，确认轨线落在允许面域。
3. 明确每条边的约束是位置连接 G0，还是与哪一张支撑面相切 G1。
4. 用带支撑面约束的填充器构造候选面；四个边角的边界条件必须兼容。
5. 修剪原支撑面，删除的仅是明确的局部条带；不能留下原条带与新面重叠。
6. 将新面、原面保留部分和需要的端部补片缝合，整理方向，形成有效实体。
7. 验证实际接缝、局部材料变化、端点和影响范围。

`BRepOffsetAPI_MakeFilling` 可作为候选底层组件，但它不是“一次调用就替换实体上的任意两张面”的工具。构造边界、裁剪原面和重建实体是 WebCAD 必须补齐的工程工作。

现有 `fittedSurface` 的点阵曲面内部 C2 不能代替上述与邻面的 G1 约束。禁止以 unconstrained loft、网格平滑、提高显示细分冒充宽圆润实现。

首版不要求跨周期缝或带内孔的整块填充。可把已明确的规则区域拆成少量兼容面片，但片间同样必须接顺，不能用分片掩盖折痕。

## 8. 平滑收口与多边交汇的算法规则

### 8.1 先判断端部应该接到哪里

对开放链每个端点收集完整邻面、原过渡面和未处理锐边，而不只看两张主支撑面。

自动计划只可选择唯一且满足当前意图的现有边界。存在多个可能接合面时，返回可视候选；跨入新的面组、改变主圆角规律或扩大过渡范围，需要新的明确请求／预览确认。

### 8.2 三类收口分别处理

**自然终止：** 保留用户允许的普通端部轮廓。新实体有效、圆角带两侧接顺即可，端部锐边单独报告。不要强迫普通长方体局部圆角把整个端面也变圆。

**接已有过渡面：** 根据被选接合面实际几何建立终端边界和切向条件。不能从产品经验预填某个小 R；也不能只令两端半径数值相等就认为相切。

**区域内渐收：** 用户提供／批准有限影响长度及可替换邻面区域，使用有约束局部补面完成。单纯 `R(s)→0`、固定小 R、在材料内放一个小端盖均不作为通用实现。两张原支撑面仍保持尖角时，过渡带收成一点可能出现奇异点，不能无条件报告普通 G1 接顺。

### 8.3 多边交汇

标准圆角的三边交汇优先统一调用内核构造。不同半径在交汇处可能兼容也可能冲突，不以“半径不同”一律拒绝；需结合真实构造和验证。对同一个切向轮廓的重复冲突定义则在调用前拒绝。

宽圆润涉及角点补片时，先由各过渡带确定兼容边界，再构造局部补片；不能分别做完每条边后用随意填充面封洞。首版覆盖规则三边交汇和规则四边界端部；高价、混合曲率复杂角点返回结构化限制，不伪造部分成功。

构造器暴露的失败轮廓、故障顶点和状态用于定位。只能报告接口确实给出的阶段，不把“起始求解失败”自动改写成“半径太大是唯一根因”。

## 9. 统一验证：不能只有 IsValid，也不能一律禁止新边

### 9.1 分层验收

| 层 | 必须检查 |
|---|---|
| 输入与结果 | 非空、有限坐标、有效 BRep；单实体输入应得到单实体；闭壳及方向正确；腔体不丢失 |
| 请求完成 | 目标范围是否覆盖；请求 R／规律或宽度有没有被改变；实际传播是否越界 |
| 圆角带 | 两侧连接位置和法向；严格模式检测要求的实际半径／规律 |
| 端点与交汇 | 自然边界是否符合声明；严格接顺区是否仍有台阶、短锐边、重叠面或奇异失败 |
| 材料 | 加料／减料语义符合局部凸凹；无意外碎体、空洞、非局部改动 |
| 保护范围 | 未授权邻面、孔、文字和锁定结构不变；需要修剪的支撑面只能改变允许面域 |
| 工程闭环 | 预览与提交一致；撤销／重做、历史改参、保存重开及 STEP 读回成立 |

一个有效实体可以有内腔和多个壳。不要固定断言 `shellCount===1`，而要核对闭合壳的合法归属和方向。圆角也可能改变外包围极值，不能把“包围盒完全不变”作为所有零件的统一条件。

### 9.2 接缝测量

使用精确 BRep；两侧法向必须对应同一个三维物理点。优先利用各面的 p-curve，并核对参数映射、面方向、位置变换以及三维重合误差。不能分别取两条参数曲线的相同比例就不再核对物理点，也不能对法向点积无条件取绝对值掩盖翻面。

覆盖整条接缝的自适应采样，增加端部邻域、曲率变化处、很短的区间。对奇异点进行单侧极限／邻域检查或返回不能验证，不能跳过后报告通过。

将结果标为“在给定容差、采样范围内通过”；不把有限采样叫数学全局 G1/G2 证明。源面本身的 G1 标签与实测结果都应保留，冲突时不放行严格结果。

短边不等于坏边，拓扑分界不等于锐边。对新增边记录：来源、关联新面、实测夹角、是否属于允许终止边。优先用构造历史定位，不能只凭新边中点靠近旧面就宣称合法。

### 9.3 半径验证

严格圆角的半径检查应基于生成圆角带对应的滚动圆／正确截面或其可靠参数映射，并区分常规带面与角点补片。不能要求整个圆角面两个主曲率处处都等于 `1/R`，也不能把任意世界坐标截面拟合出的圆当真实 R。

变 R 先验证 law 的映射和站点，再在真实圆角带上抽测中间位置。备用解析路线可利用解析参数并独立截面核对。宽圆润只验证宽度和相切等本模式要求，不套用恒 R 验收。

### 9.4 容差策略

几何容差、选择像素阈值、显示细分和输入舍入必须分开。新增一个版本化工程容差策略，记录源拓扑精度、几何尺度和每项实际阈值，不允许异常时不断放宽直到通过。

建议便携式高精度合成样例先固定位置误差 `1e-5 mm`、相切夹角 `0.1°` 作为初始测试门槛；这些是本项目建议测试值，不是行业标准，也不能直接覆盖容差更差的导入模型。生产策略必须结合源精度给出可分辨范围，并在质量不足时明确拒绝所要求的精度。

目的不是把所有 `<1°` 的边当相切：若源几何精度足以确认 0.2° 折角，它仍是真实折角。半径接近源容差数量级时返回 `RESOLUTION_INSUFFICIENT`，不能增加容差让小 R 过关。

### 9.5 材料与体积

复用／提取现有自适应体积积分。保留有符号结果和误差信息，先检查方向和闭合，不能用绝对值掩盖错误。

凸边通常切除材料，凹角可能增加材料，混合请求可以同时加减。验证局部增料和减料区域，不能只检查净体积必须下降。

存在明确切削体 C 的备用路线，核对 `V(S) ≈ V(S\C) + V(S∩C)`，并检查所有差集／交集本身有效。统一积分口径，逐级精化看结果是否收敛。容许误差应考虑积分误差和局部几何容差，既看绝对值，也看实际改动量；不能用整个大实体体积百分比遮住微小特征的大误差。

没有显式切削体的替面结果，检查 S 与结果的新增／移除区域及作用域，不套用不存在的 C。材料核对是诊断和验收的一层，不足以单独证明表面接顺。

## 10. UI 与 API 必须同次落地

### 10.1 面板

普通用户默认只看到：

```text
圆角／圆润
模式        标准 R ｜ 变 R ｜ 平滑圆润
作用范围    选边 ｜ 面边界 ｜ 面间公共边 ｜ 整件
主参数      R，或站点表，或两侧过渡宽度
相切传播    开／关，显示将增加的边
端部要求    普通终止 ｜ 要求接顺
预览        应用 ｜ 取消
```

面板按模式收窄可选范围：首版整件仅提供恒 R；宽圆润显示两侧面组及相关链，不接受未定义的“整件宽圆润”。

高级区展示两端规则、选定终止面、排除范围、只读质量报告。不要把所有 OCCT 容差和内部策略下拉框塞给用户。未实现且未验证的选项不允许点击；必须区分“本版本无实现”与“当前几何不满足条件”。

预览以高亮、透明原件、变化区域和问题位置辅助，不依赖金属高光判断。首次成功可默认展示新面、允许终止边和问题边分类；只在必要时展开完整报告。

整件明确显示将处理、跳过相切、人工排除、无法判定和失败的数量；不隐去孔内边或文字边。失败保留面板输入，不要求用户重新选一遍所有边。

### 10.2 新操作与旧操作的兼容决策

**建议新增正式操作 `rounding`，用 `specVersion:1` 和 discriminated union 描述三种模式；旧 `fillet`、`smoothTransition`、`autoRound` 保留原参数与历史语义，通过适配器共用新基础设施。**

这样不会把旧 `smoothTransition.radius` 突然解释为宽度，也不会让旧工程打开时增加新的隐式传播。新版 UI 生成新 `rounding` 特征；旧特征仍能编辑。升级旧特征到新模式是显式“转换并预览”，不是保存文件时偷偷迁移。

`chamfer` 保留现有行为，不因本次把圆角校验统一化而误套 G1 或圆弧半径校验。

`operation-registry.js` 的操作版本应按 id 管理；不要把所有 strict 操作版本一起提高。工程中的新特征须保存构造配方版本，旧程序遇到不认识的新特征要明确拒绝，而不是把它丢掉后仍称打开成功。

### 10.3 待实现参数契约

下面是新设计，不是当前已可调用的 API。Codex 须转化成仓库现有严格 schema、工具卡、读回和真实例子。

```js
// feature.add / preview.start 的 args
{
  op: 'rounding',
  opVersion: toolCard.version,
  schemaHash: toolCard.schemaHash,
  refs: [currentBody.id],
  params: {
    specVersion: 1,
    mode: 'constant', // constant | variable | blend
    scope: {
      kind: 'edges', // edges | face-boundaries | shared-faces | body
      edgeIds: currentSelection.edgeIds
    },
    propagation: 'tangent-chain',
    radiusMm: 0.5,
    boundaryRequirement: 'standard',
    endpoints: { defaultMode: 'natural' }
  }
}
```

上例中的 `toolCard`、`currentBody`、`currentSelection` 必须来自当前真实工具查询、实体和选择结果，`edgeIds` 是当前整数数组；这是待实现契约示意，不是已执行的页面调用。

字段互斥规则：

- `constant`：只接受 `radiusMm>0`；不接受站点或宽度。
- `variable`：接受按链绑定的 `laws:[{chainId,stations:[{s,radiusMm}],interpolation}]`，不接受 `radiusMm` 或宽度。
- `blend`：接受有顺序的两侧支撑面组、`widthAMm/widthBMm`，必要时使用明确接合轨线；不接受 R。首版面组需要存在明确公共边链。
- `scope.kind` 决定且只决定一组有效选择字段；显式排除字段只能用于适用范围，冲突时拒绝。
- `endpoints` 允许按有向链的 start/end 覆盖；不同模式所需 face reference／影响长度必须完整，未知字段拒绝。
- `boundaryRequirement`、保护区域和算法版本写入特征，不依赖当前 UI 设置。
- 所有长度 mm，位置比例无量纲，不应用显示精度舍入。

建议增加只读 `prepareRounding` 和 `getRoundingReport` 页面方法：

- `prepareRounding` 解析作用范围，返回当前修订绑定的链标识、方向、候选端面、实际将处理范围、适用构造器与需要补选的信息。返回 `prepared` 不代表构造一定成功。
- 预览仍用现有 `preview.start/update/commit/cancel`，不另建提交入口。
- `getRoundingReport` 读取预览／已提交特征的结构化结果，不能修改工程。

链标识、选择令牌和计划缓存只能在对应工程实例／修订有效；持久特征不得保存会话令牌作为唯一依据。`prepareRounding` 产出的临时链标识由统一页面命令层核验并转换成可持久配方，不能信任外部任意声称的“已验证 plan”。

### 10.4 报告最低字段

```text
mode / requestedSpec / effectiveSpec / strategy / solverVersion
sourceBodyId / sourceFingerprint / featureId
requestedSelection / resolvedContours / expandedSelection / skippedReasons
endpointPlans / protectedRegions
validation: solid / requestCoverage / radiusOrWidth / seams / endpoints / material
newFaceRefs / allowedTerminationEdges / problemEdgeRefs / problemVertexRefs
attempts（有界） / elapsedMs / verificationLevel
commitState / sourceRevision / resultRevision / renderedRevision（由显示层填）
```

对未知结果用 `unknown`，未执行用 `not_run`，不都填布尔 true。失败码至少区分：

`STALE_REFERENCE`、`AMBIGUOUS_SELECTION`、`SCOPE_EXPANSION_REQUIRED`、`RADIUS_LAW_CONFLICT`、`UNSUPPORTED_GEOMETRY_CLASS`、`END_CONDITION_INCOMPATIBLE`、`KERNEL_BUILD_FAILED`、`CONTINUITY_FAILED`、`MATERIAL_CHECK_FAILED`、`RESOLUTION_INSUFFICIENT`、`TIMEOUT`、`CANCELLED`。

必须扩展 Worker、适配器和 CommandService 的错误序列化白名单；仅在内核 Error 对象上挂 report 不会自动穿过现有链路。限制报告大小，几何详情用引用／分页读取，不往主线程传 OCCT 句柄或整套模型。

## 11. 历史、原子性、取消与性能

### 11.1 历史引用与回滚

改 R、改宽度应从本特征的**上游输入**重新生成，不在已经圆过的结果上叠加另一个圆角。

数字边号不是永久名称。新配方应保存来源特征／实体关系、几何描述、邻接特征、链方向和必要选点。构造历史能证明映射时重用；不能证明唯一时返回重新选择，沿用现有历史保护，不猜一个最近边。

几何指纹用于一致性与候选验证，不代表解决了所有拓扑命名问题。不同实体上的相同圆边、镜像／重复孔、保存重读后的重新编号必须测试。不要用单个 BRep 哈希当跨版本永久 ID。

一次圆润操作，不管内部有多少链和候选，只能生成一次历史事务。任一必需部分失败，原模型、历史、选择和 revision 不应被部分更新。撤销和重做同样覆盖整组。不能以 page `run` 的多步序列代替事务。

### 11.2 预览和提交

预览绑定 source revision、参数哈希、generation 和配方版本。改变参数时旧结果不能覆盖新结果；提交前检查最新代次和完整验证结果。

优先缓存已验证预览候选，避免用户点击应用时无理由重复做整套昂贵构造。缓存失效必须重建，不能提交过期实体；持久文件只保存配方和需要的正式数据，不保存预览句柄。

### 11.3 真正可取消

同步 WASM 构造可能阻塞所在 Worker。**不要只添加 AbortController 或同 Worker 的 setTimeout，就报告内核已可中断。**

优先方案：保留主页面工程为唯一权威状态；高成本试算在受控的一次性／可重置 Worker 上运行，只传递临时输入快照或可重建资料，不形成第二份可编辑工程。超时／取消由 Worker 外的管理层终止试算实例，释放资源，原工程不动。若复用正式 Worker，则必须有经过验证的重启、恢复已提交工程及未提交 UI 状态流程。

允许支持真实进度取消的绑定作为替代，但必须实测中断长计算。只忽略过期返回能解决显示竞态，不能解决 CPU 持续占用和队列阻塞，两件事分别验收。

资源策略集中配置：候选次数、站点数、边面数量、运行预算、缓存上限。预算到达返回明确状态，不让一次失败持续启动十几个试算。报告基准设备和实测时间，不用机器无关的硬性秒数伪装性能保证。

## 12. Codex 实施任务单与顺序

每个任务完成必须列出：改动文件、实际运行命令、通过／失败／未执行、正式 UI/API 入口和产出。开发可分提交点，但未经授权不 push。

### T0：固定通用基线与运行能力

- 读取本机规则和现有实现，不覆盖本地变更；记录版本。
- 先生成通用合成形状及旧工具结果，不依赖任何指定产品源文件。
- 验证锁定 WASM 必要重载；建立 `agent/output/rounding-baseline.json` 和能力证据。
- 明确已有成功集，不把已有能力包装成新增。

验收：基线与能力证据来自真实内核，尚不算工具升级交付。

### T1：建立共享管线，打通一次真实标准 R 的 UI/API/事务

- 提取拓扑、请求规划和验证模块；实现新 `rounding` 操作基本契约。
- 接入现有预览、历史、错误透传；保留旧操作行为。
- 完成一个凸边和一个凹边的真实内核贯通，包含取消和失败回滚。

验收：不是空壳接口；普通新工具能够在页面创建可编辑特征，旧工具中经独立几何核对的有效成功集无回退。旧版误报成功的缺陷应修正并单列，不能为兼容保留错误结果。

### T2：变 R 与完整轮廓传播

- 建立链方向、累计弧长和站点映射；实现两端和多站点规律。
- 核对内核自动传播，增加明确选区扩展和冲突处理。
- 覆盖不等长链、反向、闭合一致性和局部失败。

验收：真实几何读回显示不同位置达到所请求半径，不能只验证参数被保存。

### T3：受控整理和解析备用构造

- 实现等价整理策略及源几何不变测试。
- 实现第 6.2 节两个解析几何族和内部强制策略测试入口。
- 将无匹配几何族、真正几何冲突与内核失败区分。

验收：备用路线生成真实精确 BRep；并非换个参数重调原生圆角。结果材料和半径都通过。

### T4：宽度驱动的平滑圆润

- 实现两平面 Bézier 截面路线；对称／非对称宽度可编辑。
- 实现规则曲边过渡及完整有约束补面／局部替面管线。
- 接上同一 UI/API 与持久配方，不用普通 fillet 参数冒充。

验收：至少两平面非对称宽过渡、解析曲边宽过渡和一项规则四边界 G1 补面得到有效实体。缺任何一类时该分项未完成。

### T5：端点、角点与两级验收

- 实现自然／延续／已有限制面／规则相切接顺。
- 将 allowed termination 与残留缺陷分开；实现多边交汇和严格模式检查。
- 端点不兼容时返回候选作用域或定位信息，不微缩半径绕过。

验收：普通箱体局部 R 不会因允许的端边被误拒；严格圆润不能提交新台阶；规则接顺案例必须真成功。

### T6：整件范围、历史与耗时闭环

- 整件目标、排除、孔／字边、未知边全部可读回；失败时全组回滚。
- 历史改参／持久引用／重开验证，不在结果上叠圆。
- 落实外部 watchdog、取消、过期预览和恢复机制；记录内存表现。

验收：真实 WASM 长任务可以终止或恢复，普通页面工程不损坏；多组圆角一次撤销。

### T7：统一 UI、文档和公开调用

- 主入口合并到同一面板，保留必要快捷入口与旧特征编辑。
- 更新注册表、op 版本、哈希、数值元数据、UI/API coverage、页面方法、工具搜索和手册。
- 生成新工具的真实公开 API 示例，从几何查询取引用，不在示例中把边 0 当作上边。

验收：人工和 AI 能得到相同几何与报告；没有鼠标独占功能，没有新算法只在离线脚本可用。

### T8：回归与交付

执行第 13 节测试；保留固定断言，不把失败的必过样例改成“不支持也算过”。记录可选产品回归的素材缺失，但不以此阻塞通用实现。

将 UI、几何、历史、文件、显示和未完成限制分开报告。缺少真实浏览器或内核能力就写未执行，不用模拟对象测试替代几何验收。

**T0/T1 完成不能结束为“圆润工具升级完成”。完整交付需要 T2–T8 对应的必做能力闭环。**

## 13. 测试与验收矩阵

配套 `rounding-acceptance-matrix.json` 是测试规格，不是已运行结果。Codex 根据现有测试框架实现真实测试，分清三种期望：

- `must_succeed`：必须输出满足全部几何断言的结果；返回 unsupported 不算通过。
- `must_reject_unchanged`：必须明确拒绝且原工程不变。
- `must_preserve_or_match`：基线兼容、等价或 UI/API／文件往返一致性。

### 13.1 必过正向族

标准凸边、凹边、三边交汇、闭合孔口、带内腔实体；恒 R 的两平面非直角解析备用与闭合曲边备用；变 R 的直边、多段不等长链、多站点和反向等价；两侧不同宽度的宽圆润、规则曲边宽圆润、兼容四边界端部补面；普通终止、相切延续、已有终止面；整件含排除范围。

每个新增几何族至少建立尺寸变化和旋转／平移版本。对不受源精度限制的高精度合成样例测试尺度 0.1、1、10；容差策略保持单位和尺度定义一致，不能识别固定尺寸再切换产品路径。

### 13.2 必测失败和保护族

过大 R、真实薄壁碰撞、源几何无效、跨实体、非相邻／歧义面、选区扩展未授权、冲突 law、闭合首尾不一致、零／负／非有限 R、过期引用、严格区域的台阶、翻面或碎体、取消／超时、历史引用歧义。

“不支持任意曲面”不应被用作隐藏整个新增构造器未实现的理由。对扩展测试中确实未覆盖的复杂族，明确记录能力边界即可，不计入必过正向集。

### 13.3 不允许的验收替代

- `IsValid=true`、实体数为一、渲染看起来顺，不足以单独通过。
- mock 单元测试、API 收到参数、功能卡能搜索到，不足以证明新几何算法。
- 与另一 OCCT 封装比较，是封装／环境对照，不冒称完全独立几何内核证明。
- 缺客户文件的可选测试应 skip 并标注，不能把 skip 计为通过。
- 改善成功率必须同输入、同选区、同请求比较；“改成更小 R 后成功”单列，不计严格原请求成功。

### 13.4 现有验证入口

先定向执行新增内核和契约测试，再运行仓库对应命令。以下在本次核查的 `package.json` 中存在：

```sh
npm run test:contracts
npm run test:kernel
npm run test:page-api
npm run test:ui:page
npm run build
```

Node 侧不得拉起不相关产品的大规模扫描。浏览器测试使用获授权宿主通道，完成后释放控制。必要时增加 `test:rounding` 定向脚本并纳入既有测试调度；新脚本必须有实际测试实现，不只是 echo 成功。

## 14. 最终交付清单与报告模板

正式源码、UI、公开 API 和测试之外，要求生成：

```text
agent/output/rounding-baseline.json
agent/output/rounding-capabilities.json
agent/output/rounding-regression.json
agent/output/ROUNDING-TOOL-UPGRADE.md
docs/ROUNDING.zh-CN.md
```

生成文档仍按仓库脚本走，不能另写一套与注册表冲突的工具知识库。

最终报告必须包括：

1. 真正新增的几何能力、支持的几何族、运行版本。
2. 恒 R 原请求成功／失败对照；新增变 R／宽圆润的独立证据。
3. 每条通过案例的半径或宽度、接缝、端点、材料与文件读回结果。
4. UI 与公开 API 的实际执行回执；历史改参、撤销与保存重开的结果。
5. 已知不支持或未完成，哪些检查未执行及具体原因。
6. 未部署、未推送与实际磁盘产物情况，禁止把开发构建当线上已更新。

**完成判据：能通过同一个正式工具，对多种无关通用形状执行恒 R、变 R 和宽圆润；端点、作用范围和历史行为可控；UI/API/文件闭环一致。不是某一件产品终于做出来。**
