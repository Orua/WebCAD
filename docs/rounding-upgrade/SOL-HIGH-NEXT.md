当前解析路线在**同一直线、同一对平面**上的单边及 7+13 mm 共线链，已验证 2–16 站点的分段 linear R；这是可保留的子能力。它用精确圆截面和 ruled 构造，其有效性限于已验证的这个几何族。它不证明非共线链、smooth 插值、闭合周期或严格站点交汇，不能把普通 loft 自动等同于滚动圆规律。

原生路线的已知证据：

1. `Add(law,edge)` 的已试参数域失败；参考 `FilSpine::SetRadius(law)` 只创建局部 composite 而没有持久保存的实现线索。
2. 初始化前 `SetLaw/GetLaw` 因 SplitDone 未成立抛 `Standard_DomainError: ChFiDS_FilSpine::ChangeLaw : the limits are not up-to-date`。不应解释成 R 过大。
3. 非恒 R 两端初始化、真实 Contour、Simulate 之后，SetLaw 立即读回正确线性规律。
4. 同一 builder 的正式 Build 后，规律回到默认 Law_Interpol；真实 s=2/18 mm 截面 R=0.558857/1.441143，与请求 0.6/1.4 的误差约 -0.041143/+0.041143 mm。`Compute→Reset→Stripe.Reset→FilSpine.Reset` 清空临时 laws 的源码机制与此相符。
5. 包构建镜像线索指向 taucad/opencascade.js `ebd263f1` 及 OCCT `b8f597c677811d1f9f4d8a97f5ae2825c0353a42`。这是来源线索，不是 WASM 自带版本证明；`agent/temp/rounding-occt-candidate/` 参考源码须另核对实际提交，不能因目录叫 candidate 就认定已打补丁／已构建。

因此不再重试相同 Add/SetLaw 参数域。允许的下一种路线是：用户规律作为持久请求保存，Reset 清理派生缓存后按本次轮廓重新映射、生成 law 并正式求解；或证明同样规律、支撑接合、作用范围的独立构造。仅加一个同名 JS 绑定、全局删除 Reset、提交 Simulate 的旧 Shape 都不能修复。

原生候选必须处理：

- 公共站点 `s∈[0,1]`、源弧长 `S=s×整链长度(mm)`、轮廓方向和 native q 四者分开。验收例 `S∈[0,20]`、`R(S)=0.5+0.05S` 不变。
- GetBounds 的外延如 [-10,30] 是 q 使用域，不是源边站点域；从几何推映射，不写死 IC、边号或外延长度，不将整个外延重新归一化。
- 线性外推在 S=-10 达到零，属于独立外延问题。必要时在源边之外做正值、满足求解连续性的平滑延伸，源区内规律不变，保存延伸定义；不能简单截断造成导数跳变。
- GetLaw 在注入前／后、Build 后、第二次 Build、历史改参重建后分别读回；验证没用旧模拟几何。完整生命周期要包含删除／替换规律和冲突定义的失效。

## 7. 验收与节省资源的执行方式
