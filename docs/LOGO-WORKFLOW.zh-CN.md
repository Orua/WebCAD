# 从工程图复用 LOGO

WebCAD 已提供“加工 → 面与边 → LOGO”。可从 DWG、DXF、SVG、矢量 PDF、PDF 兼容 AI 或已有 `.logo.json` 导入经过核对的二维闭合轮廓，在选中的真实平面上生成凹字或凸字，保留字母内孔。它不是凭客户名称猜字体，也不把散面 IGS 自动修成产品实体。

## 直接导入文件

1. 先选中实体的一个平面，打开 LOGO 工具并选择本地文件。`.logo.json` 保持原来的纯浏览器读取；其余格式由本机 667 服务解析，不上传外部网站。
2. PDF / AI 选择页码；查看矢量轮廓，拖框圈选 LOGO，或者填写 xmin/ymin/xmax/ymax。只选需要的图案，避免把图框、尺寸线或客户栏一起选入。
3. 核对“每图纸单位对应多少毫米”和选区尺寸。PDF 默认按点换算毫米；未注明单位的图纸需要自行确认比例。
4. 点击“提取所选轮廓”，检查字形、内部镂空及实际尺寸，再设置凹凸方式与深度，预览后应用。

DWG 需要本机 LibreDWG 转换器，转换损坏的文件会明确失败；可从原 CAD 另存可靠 DXF 再试。AI 只接受以“创建 PDF 兼容文件”保存的版本，旧版 PostScript/EPS 型 AI 请先导出 SVG 或矢量 PDF。文字应在原设计软件中转曲。扫描 PDF、栅格图片、开放线条和未支持的裁剪/效果不会自动描边或替换字体；遇到不可靠轮廓应返回原设计软件修正。

源文件限 20 MiB，已有 `.logo.json` 限 2 MiB。换文件、页码、选区或比例会作废先前提取结果及建模预览，防止误用上一版字形。选区内存在未闭合或相交网络时拒绝提取，不能只看预览中的轮廓线就认定可加工。

本机安装要求：Node 服务 `scripts/serve.mjs`，以及安装了 `tools/requirements-logo.txt` 依赖的 Python。可用 `WEBCAD_PYTHON` 指向解释器，Windows 建议 pythonw.exe；其次查找本项目 `.venv`，本工作站还可复用已安装的 text-to-cad 环境。DWG 可用 `WEBCAD_DWG_CONVERTER` 指向 dwg2dxf.exe。本机服务升级后需重新启动，单独 Vite 开发服务不提供此转换接口。临时输入与转换结果在每次请求结束后清理。

## 本批图纸带来的规则

- GC15763：产品侧视图有 LANCEL 轮廓和“凹字”批注，不能只读取标题栏的客户名。
- GC16191：同一 DWG 上下两个产品视图中的 CHAVARRIA 字体不同；“双面凸字、凹位留细沙底”要求两面分别加工，凹底质感与凸字几何分开处理。不能仅凭同货号共用一份字形。
- GC16607：单侧面凹字 CHARLES & KEITH。此轮转换轮廓存在微小断口/重叠，未自动补线。
- GC16190：同时有凹字凹线条、凸边凸字；字形和菱形边框组合，不能把所有封闭区域当成同一种深度。
- GC16963、GC17092、GC17372 等 IGS 可见沿弯曲主体分布的字标；需判断承载面及投影/包覆方法，不能把平面拉伸强行当作曲面包字。
- GC15537 的 0.2 mm 是滴胶高度，不能当作凹字深度；GC17372 的抹油、GC17418 的凹位亮面属于表面工艺。当前工具不生成填油、细沙底或电镀工艺。

没有核定字深时保留为未知。界面默认 0.2 mm 仅用于示范，不能直接下发加工。

## 1. 提取可复用轮廓

工具：`tools/logo-extract.py`，依赖 `ezdxf`、`shapely`（需要支持 Polygon.normalize）。输入为可靠转换并能完整解析的 DXF。读取 DWG/DXF 的原始 SHA256、源实体编号、图框、局部窗口和单位比例作为来源记录；不修改源图。

先核对标题栏/部件/修订，把 INSERT 展开后的产品视图和 LOGO 放大检查。选择包含该货号标题的图框 `--frame`，再选择只包含目标字形的窗口 `--bounds`，坐标顺序都是 xmin ymin xmax ymax。`--mm-per-unit` 必须显式给出；按尺寸标注确认，不能只靠屏幕观感。可用 `--layer` 限定轮廓层。

示例（本批 GC15763 的已核对窗口；路径请替换为自己的转换文件和输出目录）：

```text
python tools/logo-extract.py agent/temp/logo-dwg/GC15763/gc15763.dxf --product GC15763 --frame -561 590 -368 875 --bounds -442.8 722.8 -440.2 735.1 --mm-per-unit 1 --tolerance-mm 0.005 --source-dwg G:/TEXT-TO-CAD/drawings/DWG/GC/gc15763.dwg --output <输出目录>/GC15763.logo.json
```

本工作区的 AI 在 Windows 执行 CAD Python 时，通过 text-to-cad 的 `agent/tools/cad-learning/run-silent.ps1` 启动工作区内包装脚本，避免弹出窗口；此次包装脚本在 `F:/Project/text-to-cad/agent/temp/cad-learning/`。

输出 `.logo.json` 和轮廓预览 `.logo.svg`。JSON 内为 mm 坐标，原点归一到字形包围盒中心，区域结构是 `regions:[{outer:[[x,y],...],holes:[[[x,y],...],...]}]`，最后一条边隐式闭合。SVG 仅供核对；浏览器导入的是 JSON，不执行来源文件中的 SVG 或脚本。

曲线按显式公差离散成直线段（默认 0.005 mm），因此生成的是有公差的折线轮廓，不是原始样条的无损恢复。只允许最大 0.0000001 mm 的端点数值噪声归并，记录实际移动量；不自动补设计断口、不缓冲修形。开线、相交/接触环、混货号图框和超限轮廓拒绝。跨窗口实体不提取并记录在 `excludedCrossingEntities`；必须查看预览确认整套字形完整，不能把“提取成功”当作选框正确的证明。TEXT/MTEXT 不替换为近似字体。

## 2. 浏览器加工

1. 打开或创建一个可编辑实心体，切换“面”，选择承载 LOGO 的一个平面。
2. “加工 → 面与边 → LOGO”，导入 `.logo.json`，核对名称、轮廓尺寸和预览中的内部孔洞。
3. 选择凹字/凸字，输入核定的深度或高度；设置缩放、旋转、镜像及面内偏移。
4. 预览后应用；右侧参数和历史步骤可继续修改。保存 `.webcad` 保留轮廓及来源，导出 STEP 供后续 CAD 使用。

放置原点是选中面的面积中心。局部 X 为全局 X 向面上的投影；当 `abs(normal.x)>=0.9` 时改用全局 Y 投影。局部 Y 为面法向叉乘局部 X。依次镜像 X、统一缩放、旋转，再沿局部轴偏移。正/背面分别选面处理，朝向以三维预览为准。

每个区域必须实际增减材料；越出选定面的外边界或跨过该面的孔洞会失败，凸字必须连接主体。整个操作失败不提交半成品。支持最多 150 个填充区域、每环 2000 点、总计 12000 点；复杂度超限会明确拒绝。仅支持平面，不支持曲面包覆、开放单线刻字或自动修补坏图。

## 3. AI / MCP

使用现有 `webcad_add_feature`，`op:"logo"`，`refs:[当前实体ID]`。通过 `webcad_inspect_geometry` 核实当前平面 `faceId`，再传 `regions,faceId,mode,depth,scale,angle,offsetX,offsetY,mirrorX`，可附带 `source,name,sizeMm`。从文件载入的是数据，不是任意可执行代码。

后续用 `webcad_edit_feature` 修改参数，成功后模型会更新；`webcad_refresh` 可明确重建。每次使用当前 `sessionId` 和 `expectedRevision`，不要复用旧拓扑序号。完整 MCP 接入见 [MCP 使用指南](MCP-GUIDE.zh-CN.md)。

## LOGO 脱模斜度

新建 LOGO 默认 draftAngle=7（度），可输入 0 至小于 45 度；depth 为正的雕刻深度/凸起高度，单位 mm。0° 生成直壁。承载面是中性面：其上的轮廓尺寸保持不变；凹字向底部收窄，凸字向顶部收窄，内孔反向倾斜。实际几何通过 OCCT 拔模生成，不是渲染效果。细窄笔画或深度/斜度过大导致失败时需减小参数，不自动降为 0°。

旧工程未记录 draftAngle 时按原来的 0° 重建，属性栏显示 0，避免已有模型尺寸变化。新建界面和 add_feature 默认 7°。历史参数可编辑。
